# 05 - OLED 显示

本节在 STM32F103C8T6 上使用 GPIO 模拟 I²C 驱动 0.96 英寸 OLED，并通过按键改变屏幕上的数字。

> 本文以 `keil-project` 中当前的 Keil 5 工程和源码为准。本次只整理学习笔记，不修改任何 `.c`、`.h` 或启动文件。

## 1. 学习目标

- 认识 OLED 模块的常见引脚和基本显示特点。
- 理解 SCL、SDA 在 I²C 通信中的作用。
- 理解“命令”和“数据”是两类不同的 OLED 写入内容。
- 看懂 GPIO 模拟 I²C 的开始、停止和发送字节过程。
- 学会使用现成的 OLED 显示函数，而不是一开始就背初始化命令。
- 掌握字符、字符串、十进制数、带符号数、十六进制数和二进制数的显示方法。
- 理解当前主程序如何用按键让数字递增并显示到 OLED。

## 2. OLED 模块是什么

OLED 是一种自发光显示器件，每个像素可以自行发光，因此不需要液晶屏常见的背光层。常见学习模块的分辨率为 `128 × 64`：横向 128 个像素，纵向 64 个像素。

当前字库中的每个字符占 `8 × 16` 个像素，所以屏幕可以按下面的方式理解：

```text
横向：128 ÷ 8  = 16 列字符
纵向：64  ÷ 16 = 4 行字符
```

因此本工程的字符显示函数使用：

- `Line`：第 1～4 行。
- `Column`：第 1～16 列。

这里的行、列是“字符位置”，不是单个像素坐标。

## 3. 当前工程的接线

`OLED.c` 中已经写死了当前接线：

| OLED 引脚 | STM32 引脚 | 程序中的作用 |
| --- | --- | --- |
| GND | PB6 | 输出低电平，作为当前示例的地 |
| VCC | PB7 | 输出高电平，作为当前示例的电源 |
| SCL | PB8 | I²C 时钟线 |
| SDA | PB9 | I²C 数据线 |

对应代码为：

```c
#define OLED_W_SCL(x) GPIO_WriteBit(GPIOB, GPIO_Pin_8, (BitAction)(x))
#define OLED_W_SDA(x) GPIO_WriteBit(GPIOB, GPIO_Pin_9, (BitAction)(x))
```

初始化中又把 PB7 置高、PB6 置低：

```c
GPIO_SetBits(GPIOB, GPIO_Pin_7);    // VCC
GPIO_ResetBits(GPIOB, GPIO_Pin_6); // GND
```

这是一种方便教学接线的做法。更通用、稳妥的硬件接法是让 OLED 的 VCC 和 GND 直接连接开发板的稳定电源与地，而不是长期把普通 GPIO 当作电源。使用其他 OLED 模块前还应核对模块允许的供电电压和引脚顺序，不能只凭导线颜色判断。

## 4. I²C 通信先理解什么

I²C 通常使用两根信号线：

- `SCL`：时钟线，告诉接收方什么时候读取一位数据。
- `SDA`：数据线，负责传输 0 或 1。

当前程序没有使用 STM32 内部的硬件 I²C 外设，而是由普通 GPIO 手动改变 SCL 和 SDA 的高低电平，这叫“软件 I²C”或“GPIO 模拟 I²C”。

PB8、PB9 被配置为开漏输出：

```c
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;
```

开漏输出主动输出低电平；需要高电平时释放总线，由上拉电阻把信号线拉高。许多 OLED 模块板上自带上拉电阻；如果模块没有上拉，SCL、SDA 可能无法正常得到稳定的高电平。

## 5. 一次写入是怎样完成的

### 5.1 开始信号

```c
OLED_W_SDA(1);
OLED_W_SCL(1);
OLED_W_SDA(0);
OLED_W_SCL(0);
```

当 SCL 保持高电平时，SDA 从高变低，表示一次通信开始。

### 5.2 发送一个字节

```c
for (i = 0; i < 8; i++)
{
    OLED_W_SDA(Byte & (0x80 >> i));
    OLED_W_SCL(1);
    OLED_W_SCL(0);
}
```

循环一共执行 8 次，从最高位到最低位依次发送一个字节。`0x80 >> i` 每次只保留一个目标位，`Byte & ...` 的结果决定 SDA 此时发送 0 还是 1；随后 SCL 产生一次时钟脉冲。

当前代码在 8 位之后额外产生一个时钟，但没有读取 OLED 的应答信号。这让程序更容易入门，但如果接线、地址或模块状态有问题，程序本身无法通过应答判断通信是否成功。

### 5.3 停止信号

```c
OLED_W_SDA(0);
OLED_W_SCL(1);
OLED_W_SDA(1);
```

当 SCL 保持高电平时，SDA 从低变高，表示本次通信结束。

完整流程可以记成：

```text
开始信号 → 地址 → 控制字节 → 命令或显示数据 → 停止信号
```

## 6. `0x78`、`0x00` 和 `0x40` 分别是什么

写命令和写数据都先发送：

```c
OLED_I2C_SendByte(0x78);
```

当前代码中的 `0x78` 是已经包含“写入位”的 8 位地址。换成常见的 7 位 I²C 地址表示法，它对应 `0x3C`：

```text
0x3C 左移一位，再把最低写入位设为 0 → 0x78
```

后面的控制字节决定接下来发送的内容属于哪一类：

| 控制字节 | 含义 | 后续字节的作用 |
| --- | --- | --- |
| `0x00` | 写命令 | 配置显示方向、光标、对比度、开关屏等 |
| `0x40` | 写数据 | 改变显存中的像素，从而显示图形或字符 |

所以：

```c
OLED_WriteCommand(0xAF); // 发送控制命令：开启显示
OLED_WriteData(0xFF);    // 发送显示数据：当前位置的 8 个像素置 1
```

不要把 OLED 的 I²C 地址 `0x78` 与普通显示数据混为一谈。

## 7. 屏幕坐标与光标

OLED 的 64 行像素被划分成 8 个页，每页纵向包含 8 个像素：

```text
Page 0：像素行 0～7
Page 1：像素行 8～15
...
Page 7：像素行 56～63
```

`OLED_SetCursor(Y, X)` 使用的坐标范围为：

- `Y`：0～7，选择页。
- `X`：0～127，选择横向像素位置。

但 `OLED_ShowChar(Line, Column, Char)` 为了方便使用，把字符行列换算成了底层像素位置：

```c
OLED_SetCursor((Line - 1) * 2, (Column - 1) * 8);
```

一个 `8 × 16` 字符横向占 8 个像素，纵向占连续两页，所以每个字符需要写 16 个字节：前 8 个字节画上半部分，后 8 个字节画下半部分。

## 8. 字库为什么能显示字符

`OLED_Font.h` 保存了字符的点阵数据。数组中的每一个二进制位对应一个像素：位为 1 时该像素点亮，位为 0 时该像素熄灭。

显示字符时使用：

```c
OLED_F8x16[Char - ' '][i]
```

`Char - ' '` 是把 ASCII 字符转换成字库数组下标。例如空格是字库第 0 项，字符 `'0'`、`'A'` 等会根据各自 ASCII 编码找到对应点阵。

当前字库主要用于 ASCII 可见字符，不能直接显示汉字。显示汉字需要准备对应的中文字模，并另外编写显示逻辑。

## 9. 常用显示函数

对初学阶段来说，最重要的是先会调用 `OLED.h` 中公开的函数。

| 函数 | 作用 | 示例结果 |
| --- | --- | --- |
| `OLED_Init()` | 初始化并清屏 | 使用 OLED 前调用一次 |
| `OLED_Clear()` | 清空整块屏幕 | 全屏熄灭 |
| `OLED_ShowChar(1, 1, 'A')` | 显示一个字符 | 第 1 行第 1 列显示 `A` |
| `OLED_ShowString(1, 1, "Hello")` | 显示字符串 | 从第 1 行第 1 列显示 `Hello` |
| `OLED_ShowNum(2, 1, 66, 2)` | 显示无符号十进制数 | `66` |
| `OLED_ShowSignedNum(2, 1, -66, 2)` | 显示带符号十进制数 | `-66` |
| `OLED_ShowHexNum(3, 1, 0x66, 2)` | 显示十六进制数 | `66` |
| `OLED_ShowBinNum(4, 1, 6, 4)` | 显示二进制数 | `0110` |

### 9.1 `Length` 是显示位数

`Length` 决定函数显示多少位，不是数值大小。例如：

```c
OLED_ShowNum(1, 1, 6, 2); // 显示 06
OLED_ShowNum(1, 1, 6, 4); // 显示 0006
```

当前函数会在前面补 0，不会自动补空格。

如果数字超过指定长度，函数只显示低位。例如 `OLED_ShowNum(..., 123, 2)` 显示 `23`。因此 `Length` 要与可能出现的数值范围相匹配。

### 9.2 十进制、十六进制和二进制不是三个不同的数

数值在单片机内存中仍然是一串二进制位。三个函数的区别只是把同一个数转换成不同文字形式显示出来：

```c
OLED_ShowNum(1, 1, 102, 3);      // 十进制：102
OLED_ShowHexNum(2, 1, 102, 2);   // 十六进制：66
OLED_ShowBinNum(3, 1, 102, 8);   // 二进制：01100110
```

## 10. 初始化函数应该怎样学习

`OLED_Init()` 先等待模块上电稳定，再初始化引脚，随后连续写入 SSD1306 的配置命令，最后开启显示并清屏。

初学时不需要背下全部十六进制命令。先掌握三层结构：

```text
第一层：主程序调用 OLED_Init()、OLED_ShowString() 等现成函数
第二层：显示函数把字符或数字转换成点阵数据
第三层：底层函数通过软件 I²C 把命令和数据发给 OLED
```

使用模块时主要看 `OLED.h` 的函数声明和每个函数的参数；想理解原理时，再进入 `OLED.c` 从上往下分析。

## 11. 当前主程序的运行过程

当前 `main.c` 首先初始化按键和 OLED：

```c
Key_Init();
OLED_Init();
```

然后创建一个初值为 0 的变量：

```c
int Number = 0;
```

主循环中完成三件事：

```c
OLED_ShowHexNum(3, 6, 0x66, 2);

if (Key_GetFlag() == 1)
{
    Number++;
}

OLED_ShowString(4, 1, "Number=");
OLED_ShowNum(4, 8, Number, 2);
```

实际效果为：

1. 第 3 行第 6 列显示十六进制数 `66`。
2. PB11 的按键每完成一次按下并松开，`Number` 加 1。
3. 第 4 行显示 `Number=`，并从第 8 列开始显示两位十进制数。

`Number` 没有在 99 时被程序重置；由于显示长度为 2，达到 100 后屏幕会显示 `00`，但变量本身实际仍是 100。继续按键后会显示 `01`、`02`，视觉上相当于只显示 `Number` 的后两位。

## 12. 为什么 OLED 不需要像数码管那样一直扫描

两位数码管的动态扫描需要主循环不断切换位选，否则显示会熄灭或只剩一位。OLED 内部带有显示存储器：STM32 把像素数据写进去后，OLED 控制器会自行持续刷新屏幕。

因此 OLED 内容写入一次后也能保持，不必像数码管那样每 1 ms 重复扫描。当前代码仍在 `while (1)` 中重复写相同内容，这是现有学习代码的写法，并不是 OLED 保持显示所必需的。

## 13. OLED 不亮时的排查顺序

按下面顺序检查通常最快：

1. 确认打开的是本节的 `05-oled-display/keil-project/project.uvprojx`。
2. 确认程序已经重新编译并成功下载到芯片。
3. 核对模块真实引脚顺序，不要把 VCC、GND、SCL、SDA 接反。
4. 按当前代码核对 PB6、PB7、PB8、PB9 的对应关系。
5. 确认开发板与下载器、OLED 共地。
6. 确认 OLED 模块地址与当前代码兼容；当前发送的 8 位写地址是 `0x78`，对应常见 7 位地址 `0x3C`。
7. 检查 SCL、SDA 是否具有上拉电阻。
8. 如果屏幕亮但没有文字，检查是否调用了 `OLED_Init()`，以及 `Line`、`Column` 是否超出有效范围。
9. 如果画面上下或左右颠倒，查看初始化中的 `0xA1/0xA0` 与 `0xC8/0xC0` 方向设置。

## 14. 当前代码需要留意的地方

下面这些内容按 Keil 5 源码原样保留，本次没有修改：

1. OLED 使用 PB6、PB7 模拟供电，只适合当前教学接法；实际项目通常直接使用稳定电源引脚。
2. 软件 I²C 发送函数没有读取应答信号，因此无法自动发现地址错误或器件未连接。
3. `OLED_ShowString()` 只检查字符串结尾，没有自动换行或边界检查；字符串超出第 16 列时可能显示异常。
4. `OLED_ShowNum()` 固定补前导 0，并且只显示 `Length` 指定的位数。
5. `main.c` 在循环中反复刷新固定文本和数字，能工作，但会产生许多重复通信。
6. `Key_GetFlag()` 使用阻塞方式等待 PB11 按键松开；长按期间主程序会停在按键函数中。
7. `Key.c` 调用了 `Delay_ms()`，但没有包含 `Delay.h`，完整重编译会出现两条“函数被隐式声明”警告。
8. `Key.c` 和 `Seg.c` 的文件末尾没有换行，完整重编译会各出现相应警告。
9. 工程仍保留 LED、数码管等上一节模块，但当前 `main.c` 没有初始化和使用它们。

## 18. 本节小结

- 当前 OLED 是通过 PB8、PB9 模拟 I²C 通信，PB6、PB7 按现有代码模拟 GND、VCC。
- `SCL` 负责时钟，`SDA` 负责数据；开漏总线需要上拉才能得到可靠高电平。
- `0x78` 是当前使用的 8 位写地址，对应 7 位地址 `0x3C`。
- `0x00` 表示后面发送命令，`0x40` 表示后面发送显示数据。
- `8 × 16` 字符让 128×64 屏幕形成 4 行、每行 16 列的字符区域。
- 实际使用时先读 `OLED.h` 学会函数调用，再按需要深入 `OLED.c` 的底层实现。
- OLED 写入显存后可以保持显示，不需要像动态数码管那样持续扫描。
- 当前程序通过 PB11 按键让 `Number` 递增，并以两位十进制形式显示。

# 12 - Bitwise Operations

位运算是嵌入式 C 的核心基础。STM32 的寄存器由许多个二进制位组成，每一位或每一组位可能控制一个硬件功能。

本章不会只介绍运算符，而是重点学习如何用“位掩码”安全地修改指定的位。

## 学习目标

完成本章后，你应该能够：

- 看懂二进制、十六进制与位编号
- 使用 `&`、`|`、`^`、`~`、`<<` 和 `>>`
- 创建位掩码
- 对某一位进行置位、清零、翻转和检查
- 修改一个多位字段而不影响其他位
- 理解这些操作如何用于 STM32 寄存器

## 1. 二进制与十六进制

计算机中的整数最终以二进制保存。一个 8 位无符号数可以写成：

```text
位编号： 7 6 5 4 3 2 1 0
二进制： 1 0 1 0 0 1 0 1
```

最右侧是第 0 位，向左依次是第 1 位、第 2 位……

二进制很长，因此查看寄存器时经常使用十六进制：

```text
二进制 1010 0101
十六进制 0xA5
```

每 4 个二进制位正好对应 1 个十六进制数字。

## 2. 为什么优先使用无符号整数

位运算通常使用无符号类型，例如：

```c
#include <stdint.h>

uint8_t value8;
uint16_t value16;
uint32_t value32;
```

这些类型明确表示 8、16、32 位无符号整数。位移有符号数，特别是负数，容易产生不直观或与实现有关的结果。

整数常量后面的 `U` 表示无符号：

```c
1U
0x0FU
```

## 3. 六个位运算符

### 3.1 按位与 &

两个对应位都为 `1`，结果才为 `1`。

```text
1010
1100
---- &
1000
```

常见用途：检查某个位、清除某个位、提取一个字段。

### 3.2 按位或 |

只要有一个对应位为 `1`，结果就是 `1`。

```text
1010
1100
---- |
1110
```

常见用途：把某一位置为 `1`。

### 3.3 按位异或 ^

两个对应位不同，结果为 `1`。

```text
1010
1100
---- ^
0110
```

常见用途：翻转指定的位。

### 3.4 按位取反 ~

把每一位的 `0` 和 `1` 互换。

```text
原值：0000 0101
取反：1111 1010
```

注意：整数表达式可能发生“整数提升”，所以给较小类型赋值时可能需要显式转换。

### 3.5 左移 <<

```c
1U << 3
```

把二进制 `1` 左移 3 位，得到第 3 位为 `1` 的数：

```text
0000 0001 -> 0000 1000
```

它是创建位掩码最常用的方式。

### 3.6 右移 >>

```c
value >> 2
```

把所有位向右移动 2 位。常用于把某个字段移动到最低位后读取。

## 4. 位掩码

位掩码是一个用来选择特定位的数。

```c
#define BIT(position) (1U << (position))
```

`BIT` 是一个宏。调用 `BIT(3)` 时，预处理器会把参数 `position` 替换成 `3`：

```c
BIT(3)

/* 展开后相当于 */
(1U << 3)
```

`1U` 的 8 位二进制表示可以看作：

```text
0000 0001
```

左移 3 位：

```text
0000 0001  原来的 1U
0000 0010  左移 1 位
0000 0100  左移 2 位
0000 1000  左移 3 位，也就是 BIT(3)
```

位编号从最右侧的 `0` 开始：

```text
位编号：7 6 5 4 3 2 1 0
BIT(3)：0 0 0 0 1 0 0 0
                ^
               第3位
```

因此，`BIT(3)` 的作用不是直接修改变量，而是先产生一个“只有第 3 位为 `1`”的数。这个数就是用来选择第 3 位的掩码。

常见掩码如下：

```text
BIT(0) = 0000 0001
BIT(1) = 0000 0010
BIT(2) = 0000 0100
BIT(3) = 0000 1000
BIT(4) = 0001 0000
```

宏的参数和整个表达式都加括号，可以降低替换后运算顺序出错的风险。

## 5. 四种最重要的单比特操作

假设变量名是 `register_value`，要操作第 3 位。

### 5.1 置位：设为 1

```c
register_value |= BIT(3);
```

`|=` 是复合赋值运算符，完整写法是：

```c
register_value = register_value | BIT(3);
```

它不是直接把 `BIT(3)` 覆盖到整个变量，而是完成三步：

1. 读取 `register_value` 原来的值
2. 原值与 `BIT(3)` 的每个对应位进行按位或
3. 把结果重新保存到 `register_value`

例如：

```text
register_value：1010 0001
BIT(3)：        0000 1000
按位或结果：    1010 1001
```

按位或的关键规律是：

```text
原位 | 0 = 原位
原位 | 1 = 1
```

`BIT(3)` 只有第 3 位是 `1`，因此：

- 第 3 位与 `1` 进行或运算，无论原来是什么，结果都为 `1`
- 其他位与 `0` 进行或运算，全部保持原值

所以 `register_value |= BIT(3)` 能够只把第 3 位置为 `1`。

如果写成下面这样：

```c
register_value = BIT(3);
```

整个变量就会变成 `0000 1000`，原来其他位置的数据都会丢失。

### 5.2 清零：设为 0

```c
register_value &= ~BIT(3);
```

先将掩码取反，使第 3 位为 `0`、其他位为 `1`，再执行按位与。

### 5.3 翻转

```c
register_value ^= BIT(3);
```

原来为 `0` 就变成 `1`，原来为 `1` 就变成 `0`。

### 5.4 检查

```c
if ((register_value & BIT(3)) != 0U)
{
    printf("Bit 3 is set\n");
}
```

这里的目标不是判断整个变量是否等于 `BIT(3)`，而是检查对应位是否不为 `0`。

## 6. 操作多位字段

前面的 `BIT(3)` 只选择一个位。但寄存器中的一个功能也可能由连续多个位共同表示。

例如，规定第 4～5 位共同保存工作模式：

```text
位编号：7 6 5 4 3 2 1 0
模式字段：    [5 4]
```

两个二进制位可以组成四种数值：

```text
第5～4位
00 = 模式 0
01 = 模式 1
10 = 模式 2
11 = 模式 3
```

所谓“2 位字段”，就是把两个相邻的二进制位置看作一个整体，用它保存范围为 `0～3` 的模式编号。

### 6.1 为什么掩码使用 3

先定义位置和掩码：

```c
#define MODE_POSITION 4U
#define MODE_MASK (3U << MODE_POSITION)
```

这里的 `3` 不是模式值，而是用来制作一个具有两个 `1` 的掩码。

十进制 `3` 的二进制是 `0000 0011`：

```text
3U：          0000 0011
3U << 4：     0011 0000

位编号：      7 6 5 4 3 2 1 0
MODE_MASK：   0 0 1 1 0 0 0 0
                  ^ ^
                 第5、4位
```

“掩码覆盖两个位”的意思是：掩码的第 4 位和第 5 位都是 `1`，所以后续位运算可以同时选中这两个位置。

### 6.2 “写入值 2”是什么意思

假设设备需要进入模式 `2`。十进制 `2` 的二进制是 `10`，正好可以放进这个两位字段。

但是 `10` 目前位于最低两位，必须左移 4 位，把它移动到第 4～5 位：

```text
2U：          0000 0010
2U << 4：     0010 0000

位编号：      7 6 5 4 3 2 1 0
移动后：      0 0 1 0 0 0 0 0
                  ^ ^
                  1 0 = 模式2
```

因此，“写入值 `2`”就是把二进制 `10` 保存到寄存器的第 4～5 位。

### 6.3 为什么要先清除旧字段

假设寄存器原值是：

```text
register_value = 1011 1101
```

其中第 4～5 位原来是 `11`，也就是模式 `3`。现在想把它改成 `10`，也就是模式 `2`。

如果直接使用按位或：

```text
原值：        1011 1101
模式2：       0010 0000
直接按位或：  1011 1101
```

第 4 位原来是 `1`，与新值中的 `0` 进行或运算后仍然是 `1`，所以字段没有正确变成 `10`。因此必须先清除旧字段。

掩码及其 8 位取反结果可以理解为：

```text
MODE_MASK：    0011 0000
~MODE_MASK：   1100 1111
```

使用原值与取反后的掩码进行按位与：

```text
原值：                 1011 1101
取反后的掩码：         1100 1111
清除字段后的结果：     1000 1101
                            ^^
                            00
```

第 4～5 位被清成 `00`，其他位置保持原值。

### 6.4 完整写入过程

写入值 `2`：

```c
register_value =
    (register_value & ~MODE_MASK) |
    ((2U << MODE_POSITION) & MODE_MASK);
```

使用刚才的示例数值，整个过程是：

```text
原寄存器：             1011 1101
清除第4～5位后：       1000 1101
移动后的模式2：        0010 0000
按位或写入后：         1010 1101
                            ^^
                            10 = 模式2
```

完整代码可以概括成：

```text
新寄存器值 = 清除旧模式后的原值 | 移动到正确位置的新模式
```

代码的四个步骤是：

1. 使用 `& ~MODE_MASK` 清空原字段
2. 把新值移动到正确位置
3. 使用 `& MODE_MASK` 限制新值的范围
4. 使用 `|` 写入字段

其中 `& MODE_MASK` 是保护措施：如果传入的模式值超过两位能够保存的范围，只保留属于第 4～5 位的部分。

### 6.5 读取字段

读取字段：

```c
uint8_t mode = (register_value & MODE_MASK) >> MODE_POSITION;
```

读取分为两步：

1. `register_value & MODE_MASK` 只保留第 4～5 位
2. `>> MODE_POSITION` 把它们右移回最低位，得到普通数值 `0～3`

例如：

```text
寄存器值：             1010 1101
与掩码操作后：         0010 0000
右移4位后：            0000 0010 = 2
```

## 7. 运算优先级与括号

位运算表达式很容易因为运算优先级而被误读。即使你记得优先级，也建议加括号：

```c
if ((value & mask) != 0U)
```

不要写成含义不清楚的长表达式。硬件控制代码首先要便于检查。

## 9. 与 STM32 的联系

STM32 寄存器操作经常出现类似代码：

```c
register_value |= BIT(5);     /* 设置第 5 位 */
register_value &= ~BIT(5);    /* 清除第 5 位 */
```

真实芯片的寄存器通常已有官方宏定义，不需要总是自己写 `BIT`。你要重点理解这些宏最终在做什么。

以后看到这种代码：

```c
GPIOA->ODR |= GPIO_ODR_OD5;
```

就可以把它理解为：在 GPIOA 输出数据寄存器中，把控制某个引脚的位设置为 `1`。

实际使用寄存器前必须查看芯片参考手册。有些状态位需要特殊方式清除，不能对所有寄存器机械地使用同一套读—改—写操作。

## 10. 常见错误

1. 把逻辑运算 `&&`、`||` 与位运算 `&`、`|` 混淆。
2. 清零时写成 `register_value &= BIT(3)`，这会保留第 3 位并清除其他位。
3. 检查位时写成 `register_value == BIT(3)`，导致其他位为 `1` 时判断失败。
4. 对有符号负数进行位移。
5. 移动的位数大于或等于类型宽度，这会导致未定义行为。
6. 写多位字段前没有先清除旧值。
7. 操作真实寄存器前没有阅读参考手册。
